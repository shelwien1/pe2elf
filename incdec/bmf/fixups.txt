# fixups.txt — per-function literal substitutions applied to the donor body
# before extraction.  Tab-separated: function, find, replace, why.
#
# This is for the cases incdec.md §8 is about: Hex-Rays emits something its own
# type model implies but that g++ will not compile.  Every entry here is a
# *reinterpreting cast* — on i386 all of these are 4-byte-to-4-byte, so they
# change no code, only what the front end will accept.  Anything that would
# change behaviour belongs in override/ as a hand-written .inc, not here.
#
# `find` is matched literally against BMF.c, so you can grep for it, and
# extract.py fails loudly if it stops matching — a fixup cannot rot silently
# into a no-op when the donor is re-decompiled.
#
sub_412E60	v32[1] -= v52;	v32[1] -= (unsigned int)v52;	v52 is a counter (`v52 = (unsigned __int16 *)((char *)v52 + 1)`) that Hex-Rays typed as a pointer. `unsigned -= pointer` is not valid C either; the instruction is `sub [ecx+4], edx`.

sub_424D90	sub_4248D0(v104, v103, (int)v102);	sub_4248D0(v104, (_DWORD *)v103, (int)v102);	As above.

sub_424550	v39 = v38 - *(_DWORD *)(this + 8);	v39 = v38 - *(int *)(this + 8);	`__int64 v39` fed to `(BYTE4(v39) ^ v39) - BYTE4(v39)`, the sign-mask abs() of `cdq; xor eax,edx; sub eax,edx` at 0x004247FA. `int - _DWORD` is *unsigned*, so widening to __int64 zero-extends, BYTE4 is always 0 and the abs vanishes. sub_412E60	v43 = (unsigned __int16 *)((char *)v43 - 1);	v43 = (unsigned __int16 *)((uintptr_t)v43 - 1);	v43 is the `dec edi; jnz` counter of the insertion sort at 0x0041314E, which Hex-Rays typed as a pointer because the slot it lives in holds one elsewhere. `p - 1` on a pointer can never be null in C, so g++ folds `while ( v43 )` to `while ( 1 )` and the loop walks off the array — the `jmp` back at 0x3000b4e9 with no test. Laundering the arithmetic through uintptr_t makes the value integer-derived, which may legitimately be null. Same address arithmetic.
